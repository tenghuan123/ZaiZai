# 桌面任务助手首版开发计划

计划日期：2026-11-02。范围来自 [需求文档](requirements.md)，技术基线采用 [技术选型建议](technical-selection.md)，实现职责与接口按 [应用架构](architecture.md) 和 [数据模型](data-model.md)。

先完成 2 至 3 人日的双平台技术原型，再实现任务闭环、提醒和宠物，最后交付可安装版本。按一名熟悉 TypeScript 的开发者全职投入估算，首版约 **22 至 30 人日，约 5 至 6 个工作周**。这是工作量区间，不是已确定的上线日期。

该估算覆盖一套内置素材的核心闭环。原型中的完整宠物资源管理与本地导入作为 X1 批次，暂估追加 3 至 5 人日，待素材和导入格式样本明确后复核。浏览器原型已具备，本机 macOS M0 核心链路已执行，Windows 及其余原生验收见 [M0 验证记录](m0-verification.md)，不能将本机结果抵作双平台全部完成。

## 1 估算前提

- 当前范围包含日/周/月周期与一天多个时间，不含法定节假日规则、间隔重复、稍后提醒和跨设备同步。
- 一套可接入的宠物素材由现成资源或用户提供；原创绘制和反复改稿不计入开发人日。
- 能取得 Windows 和 macOS 测试环境，至少覆盖 Windows x64 与 Mac Apple Silicon。
- 能及时取得用于真实通知与分发验证的签名条件；证书办理和外部等待不计入开发人日。
- 视觉目标是参考图所示的紧凑清单与宠物组件，首版不增加复杂主题系统。
- 默认由一人顺序推进；阶段表没有通过假设多人并行压缩时间。
- 目前已有浏览器原型、Electron M0、M1 正式数据服务与 M2 任务界面；任务编辑、计划管理、日期历史与迁移均已接通。双平台验收仍未完成，原生验证缺口继续保留。阶段证据见 [M1 验证记录](m1-verification.md) 与 [M2 验证记录](m2-verification.md)。

## 2 阶段与交付物

| 阶段 | 工作包 | 对应功能 | 工作量 | 可验收交付物 |
| --- | --- | --- | --- | --- |
| M0 | 双平台能力验证与范围收敛 | F07、F08、F10 至 F12 的关键风险 | 2 至 3 人日 | 两个平台安装原型、通知与后台行为记录、资源基线、明确技术选择 |
| M1 | 工程基础与数据边界 | F11、F13 及公共基础 | 2 至 3 人日 | 主进程、preload、界面分层；数据库迁移、设置、单实例与失败提示 |
| M2 | 任务与日期闭环 | F01 至 F06 | 4 至 6 人日 | 一次性与日/周/月多时间任务、计划管理、今日清单、历史与进度 |
| M3 | 提醒与后台生命周期 | F07、F10、F12 | 3 至 4 人日 | 定时通知、点击定位、隐藏与退出、恢复汇总、提醒处理记录 |
| M4 | 宠物与完整界面 | F08、F09、F13 | 3 至 4 人日 | 精灵图互动、事件反馈、时钟与下班倒计时、主要界面样式 |
| M5 | 双平台回归与安装交付 | 全部 P0 | 4 至 5 人日 | 验收记录、安装包、数据迁移验证、使用说明与已知限制 |
| 缓冲 | 兼容性与交付修复 | 根据实测问题安排 | 4 至 5 人日 | 修复透明窗、通知、原生模块或安装差异 |
| 合计 | 首版完整交付 | P0 | 22 至 30 人日 | 双平台本地桌面应用 |

正常推进顺序为 M0 → M1 → M2 → M3 → M4 → M5。M0 是技术样本，不视为全部功能完成；后续使用同一技术路线收敛实现，避免一次性样本变成长期维护的第二套程序。

## 3 各阶段任务与通过标准

### M0 双平台能力验证

任务：

- 初始化最小 Electron 样本，锁定 Electron、构建、打包与 SQLite 驱动版本。
- 制作透明无边框窗口，放入示例宠物、一个任务输入框和按钮。
- 验证点击、拖动、焦点、透明区域遮挡和多屏恢复。
- 验证完整清单与仅桌宠之间的原生边界切换，确保收起后没有大片透明区域继续阻挡桌面。
- 增加 Windows 托盘与 macOS 菜单栏入口，验证隐藏、恢复和退出。
- 在安装包中完成定时通知、点击定位与 SQLite 读写；macOS 使用符合所选版本要求的签名应用。
- 做一次隐藏到点和一次休眠恢复测试，记录失败路径及系统权限状态。
- 测量可见、隐藏与动画播放时的资源，明确最低系统版本、目标架构和通知点击范围。

通过标准：双平台关键路径均有实际记录；不能只提交截图或开发模式录屏。某项未通过时先修正方案或界面边界，再进入正式任务开发。若缺少其中一平台、签名条件或可用素材，记录具体缺口，不将未验证项标成通过。

### M1 工程基础

任务：

- 确定目录和进程边界，定义少量类型明确的业务命令。
- 实现数据库初始化、版本迁移和迁移前备份。
- 实现用户数据目录、设置保存、单实例限制与窗口位置恢复。
- 保持界面隔离，保存与读取失败时向界面返回可处理结果。
- 建立格式、类型检查、打包脚本与任务规则的自动化测试入口。

通过标准：安装后的应用可保存设置和一条示例任务，重启后恢复；写入失败时界面不显示保存成功；没有直接从页面访问数据库的第二条写入路径。

### M2 任务闭环

任务：

- 实现一次性任务、日/周/月周期计划、优先级与多时间槽。
- 实现实例生成与去重、计划编辑、暂停、恢复和结束。
- 实现完成、撤销、删除本次、查看已完成和按日期查看已有历史。
- 实现跨天切换、未完成保留、移到今天，以及今日进度。
- 为日期、去重、生效范围和统计编写有意义的规则测试。

通过标准：A01 至 A05、A13 通过；同一天多次执行互不影响，重启不产生副本，历史不会被修改计划覆盖。此时可交付任务功能试用版，提醒与宠物仍按后续阶段验收。

### M3 提醒与生命周期

任务：

- 在主进程实现最近到期调度、低频校验和任务变动后重新安排。
- 实现稳定通知标识、提醒处理记录、失败与恢复路径。
- 处理同时到点、提前完成、撤销完成、删除和计划暂停。
- 处理跨天、休眠恢复、应用重启和系统时间变动。
- 完成关闭选择，以及托盘或菜单栏直接退出的不同路径。
- 在安装后的两个平台中验证通知点击定位与权限关闭后的行为。

通过标准：A06 至 A09、A14 通过；隐藏不影响调度，退出停止新提醒；同一时刻多项到点汇总，普通重启不重复提交已处理提醒。

### M4 宠物与完整界面

任务：

- 明确精灵图规格，接入待机、点击回应、庆祝与提醒动作。
- 区分宠物点击和拖动，处理动画打断与气泡定位。
- 将动作绑定到已经成功的业务结果，避免动画驱动数据修改。
- 完成今日清单、任务编辑、计划管理、历史和设置界面。
- 加入日期、星期、固定下班时间与真实时间差倒计时。
- 优化长文本、滚动、键盘提交与隐藏时的动画暂停。

通过标准：A10 通过；主要操作都可在完整界面完成；休眠或隐藏后恢复不会导致倒计时错误、动画堵塞或按钮不可点。

### M5 验收与分发

任务：

- 按需求文档 A01 至 A14 执行双平台安装后回归。
- 验证不同缩放、外接显示器断开、长列表与资源回收。
- 验证覆盖安装、数据库迁移、异常退出及本地数据保留。
- 生成平台安装包，处理 macOS 签名公证及 Windows 分发签名准备。
- 编写运行、隐藏、退出、通知设置、数据位置和版本升级说明。
- 记录素材来源，整理已知限制与真实测试范围。

通过标准：P0 无阻塞问题；每个平台都有安装包、系统与架构信息和验收记录。未完成签名、公证或安装测试的构建应明确标为测试构建，不能称为完整发布交付。

### X1 宠物资源管理扩展

覆盖原型已展示的资源库：内置与本地角色选择、缩放和锚点覆盖、精灵图参数、文件夹或 zip 导入、受限资源协议，以及缺失动作回退。GIF 或动态 WebP 使用文件自身播放参数，帧率设置仅用于精灵图。

先复用 M4 已验证的播放器，再实现资源发现和导入；不改变任务身份、时间规则和提醒记录。暂估追加 3 至 5 人日，不包含素材制作。通过标准为导入失败不影响原角色，切换和重启后配置保留，资源错误不影响任务与提醒。

## 4 重点测试

自动化测试优先覆盖容易出错且可重复验证的业务规则，不为简单样式和机械配置堆叠测试。

| 类型 | 重点 |
| --- | --- |
| 规则测试 | 同日多时间、跨天、开始结束边界、计划编辑和暂停、移到今天、空清单统计 |
| 数据集成 | 实例唯一性、重复命令、事务失败、完成与撤销、迁移回滚或恢复 |
| 提醒集成 | 提前完成、同时到点、重启去重、提交前后异常中断、通知失败 |
| 安装后验收 | 通知权限与点击、托盘或菜单栏、隐藏继续提醒、退出、休眠恢复 |
| 视觉与交互 | 精灵图锚点、点击拖动区分、透明空白、缩放、焦点和多屏 |

系统通知、窗口层级和多显示器行为必须有真机验证。可以使用虚拟时间测试任务规则，但不能用虚拟时间结果代替真实休眠和平台通知测试。

## 5 依赖与排期风险

| 依赖 | 最晚处理阶段 | 影响与处理 |
| --- | --- | --- |
| Windows 与 Mac 测试设备 | M0 | 少一个平台就只能报告单平台结果，不把兼容性验证推迟到交付后 |
| 签名条件与通知权限 | M0；完整分发配置在 M5 | 开发运行不等于真实通知可用；凭据申请等待单独记入日历计划 |
| 一套可用宠物素材 | M4 前 | M0 可用占位帧验证交互；正式观感与素材准备分开估算 |
| 系统版本与芯片架构 | M0 | 新增 Windows ARM、老系统或 Intel Mac 时重新评估构建和验收工作量 |
| 透明窗口与鼠标命中 | M0 | 优先收紧窗口边界，复杂逐像素穿透或独立游走单独拆需求 |
| 原生 SQLite 依赖 | M0 | 先验证两个平台安装包，避免在发布阶段才遇到 ABI 或构建问题 |
| 未运行历史与旧通知激活规则 | M0 | 按需求文档默认值收敛；需要扩展时调整数据与恢复设计 |

## 6 迭代顺序

- 第一轮原型：只验证技术风险，2 至 3 人日。
- 第二轮任务试用：完成 M1 和 M2，让用户确认任务、重复计划与历史操作。
- 第三轮完整体验：完成 M3 和 M4，验证提醒与宠物是否符合日常使用习惯。
- 第四轮交付：完成 M5 与必要修复，提供双平台安装包和使用说明。

指定星期/月日期重复、开机启动和内置多角色选择已接入。后续优先补齐双平台安装验收，再考虑稍后提醒、备份导出、用户素材导入与轻量打卡。是否增加这些功能，以首版试用反馈决定。

## 7 完成定义

交付完成同时满足：需求验收通过、双平台安装后验证通过、本地数据可恢复、素材来源明确、分发条件明确、文档与实际行为一致。只有任务界面或宠物动画演示，不视为首版交付完成。

2026-11-03：v0.3 六项扩展已接入正式源码，检查结果及平台边界见 [v0.3 验证记录](v0.3-verification.md)。本页原阶段工作量是历史估算，不代表已完成双平台分发验收。
