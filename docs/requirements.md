# 桌面任务助手与互动宠物需求文档

版本：0.2。基线日期：2026-11-02。补充优化原型进入架构阶段的对接规则。

目标是让用户通过一个常驻桌面的小组件，安排日常生活与临时事项，在指定时间收到提醒，并通过宠物互动获得反馈。首版围绕任务、提醒、宠物和本地桌面体验形成完整闭环。

依据为用户提供的参考截图，以及本次对话中对任务类型、宠物互动、关闭行为和存储范围的确认。截图上方的关注、分享、头像和图片页码属于发布平台，不计入应用范围。

## 1 范围与决策状态

### 1.1 用户明确确认

| 项目 | 决定 |
| --- | --- |
| 目标平台 | Windows、macOS 桌面应用 |
| 任务类型 | 支持长期重复任务，以及今天等指定日期的一次性任务 |
| 日常场景 | 吃药提醒、起身运动、准备早饭午饭晚饭等，由用户自行设置内容与时间 |
| 宠物 | 可以互动，使用精灵图动画；素材可自行制作或寻找现成资源 |
| 关闭行为 | 点击关闭按钮后，让用户选择隐藏或退出 |
| 数据 | 仅保存在本机，不做跨设备同步 |
| 下班时间 | 固定时间，可在设置中修改 |
| 打卡 | 首版不做；如以后增加，仅表示进入应用开启新一天 |

### 1.2 上一轮方案中已接受的首版默认规则

- 重复任务首版支持每天重复，同一天支持多个执行时间；每一次执行独立完成。
- 今日清单合并当天的重复任务与一次性任务，支持待办、已完成切换及今日进度。
- 任务可以完成、撤销完成；重复计划可以暂停、恢复和结束，历史完成记录保留。
- 前一天未完成的任务保留在历史中，可以手动移到今天，不自动清空或自动完成。
- 窗口隐藏后保持运行与提醒；退出应用后停止提醒。
- 休眠期间错过的提醒在恢复后汇总，不逐条连续补弹。
- 宠物首版接入一套素材，提供待机、点击反馈、完成庆祝和提醒动作。
- 首版建议宠物与清单共同组成一个小组件，拖动时一起移动。

### 1.3 新增的实施默认值

以下是使开发边界明确的建议，尚不是用户逐项确认的细节；可以在原型阶段调整。第 4 至第 7 节中超出前述确认范围的具体交互与边界处理，同样属于建议默认值。

| 项目 | 建议默认值 |
| --- | --- |
| 时间基准 | 按电脑当前本地日期与时区安排后续任务，保留历史完成记录 |
| 空清单进度 | 显示 0/0 和“今天还没有任务”，进度条为 0%，不触发全部完成庆祝 |
| 固定下班时间 | 每个自然日使用相同时间；未配置时引导设置，到点后显示“已下班” |
| 通知点击 | 应用运行时，点击通知显示窗口并定位任务；退出后的旧通知激活另行验证 |
| 未运行日期 | 首版启动时补齐当天安排；历史只展示已生成的任务记录，不假定未运行日期的执行情况 |
| 窗口形态 | 普通桌面浮窗，固定默认尺寸；是否置顶作为设置项，先在原型中验证 |
| 关闭选择 | 每次点击组件关闭按钮都显示“隐藏到托盘/菜单栏”“退出软件”“取消” |

## 2 任务概念

“长期任务”在首版中表示重复计划，不表示一条一直不能结束的任务。

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 一次性任务 | 在指定日期执行一次，时间可选 | 今天整理文件 |
| 重复计划 | 定义每天在哪些时间执行什么事项 | 每天 10:00、15:00 起身运动 |
| 任务实例 | 某一天某一次实际需要完成的事项 | 今天 10:00 起身运动 |
| 完成记录 | 某个实例的完成状态及完成时间 | 今天 10:08 完成上午运动 |

完成一个实例，只影响该次执行。编辑重复计划，不改写既有完成记录。今日进度按实例统计：同一计划每天执行两次，计为两项任务。

## 4 任务业务规则

### 4.1 创建与展示

- 快捷新增默认创建今天的一次性任务；设置日期、时间或重复规则时进入任务编辑面板。
- 任务名称去除首尾空白后不能为空。长度限制在界面原型阶段确定，并验证长文本换行。
- 重复计划至少有一个时间，同一计划内不允许重复的时间；开始日期不得晚于结束日期。
- 待办默认按时间升序排列，无时间任务置于其后；已完成列表建议按完成时间倒序。
- 未到时间的当天任务也出现在今日清单中，可以提前完成；已完成任务到点不再提醒。

### 4.2 完成与统计

- 完成与撤销操作立即更新列表和进度，保存成功后才向用户确认成功；写入失败时保留可重试入口。
- 进度为“当天已完成实例数 / 当天有效实例总数”，百分比四舍五入为整数。
- 提醒、关闭气泡和关闭系统通知都不代表任务完成。
- 新增、删除、移入或移出当天任务后重新计算进度，不能将进度当成只增不减的数值。
- “全部完成”庆祝只在用户完成任务使非空清单从未全部完成变为全部完成时触发；空列表和启动恢复不触发。

### 4.3 编辑与结束重复计划

- 首版在计划管理中编辑重复规则，影响后续尚未到点的安排；已到点或已完成的实例保留原记录。
- 暂停后取消后续尚未到点的安排；恢复后从当前时刻继续安排，不为暂停期间补发提醒。
- 结束计划停止后续安排，保留已发生记录。重新建立相同事项时创建新计划。
- “删除本次任务”和“结束重复计划”使用不同操作与文案，避免误删整条计划。
- 删除本次重复任务仅移除该次有效安排，不影响之后的日期；首版不提供“仅本次修改时间”编辑模式。
- 结束日期为包含当天：该日期仍可产生执行实例，次日起不再产生。

### 4.4 跨天与历史

- 新的一天不依赖打卡，应用运行期间自动切换日期并生成当天清单。
- 昨天未完成的实例保留在原日期，不自动加入今天，不自动设为完成。
- “移到今天”保留任务实例身份与原始计划时间，改变其执行日期；同一天重复点击不产生副本。
- 对重复任务，移来的旧实例和今天原本的实例可以同时存在，界面应标明旧实例的原日期。
- 历史中的完成和撤销操作更新该实例所属执行日期的统计。

## 5 提醒与时间规则

| 场景 | 期望行为 |
| --- | --- |
| 正常运行到点 | 向系统提交一次通知；窗口可见时显示宠物提醒气泡 |
| 同时多项到点 | 汇总提示，点击进入到点任务列表；不连续抢占界面 |
| 窗口隐藏 | 继续调度和提交系统通知，不强制弹出主窗口 |
| 已完成或已删除 | 不再提醒该实例 |
| 撤销完成 | 已提醒过的实例不立即重复提醒；尚未到点且未提醒的实例正常等待到点 |
| 休眠后恢复或重新启动 | 汇总当天已到点、未完成且未提醒的事项；不逐条补发旧日期通知 |
| 系统拒绝或关闭通知 | 任务继续可用；显示通知不可用状态与系统设置指引，不标记任务完成 |
| 退出或电脑关机 | 应用不再产生新提醒；下次启动恢复数据并执行当日检查 |
| 日期或系统时间改变 | 按当前时间重新计算后续安排，不通过倒计时累计推测日期 |

提醒结果与任务完成状态独立。应用应持久化提醒处理记录，避免普通重启和重复调度造成连续通知。系统是否展示通知受系统设置控制；应用需要记录提交或失败状态，不能将“提交成功”展示为“用户已经收到”。

## 6 宠物与桌面交互

| 事件 | 动画与交互 |
| --- | --- |
| 待机 | 循环呼吸、眨眼或小动作 |
| 点击 | 播放回应动作，可出现简短气泡 |
| 完成一项任务 | 播放一次开心或庆祝动作 |
| 全部任务完成 | 播放一次单独的庆祝反馈 |
| 到点提醒 | 提醒动作与任务气泡，点击气泡进入对应任务 |
| 拖动 | 宠物与任务组件共同移动，释放后记住窗口位置 |
| 窗口隐藏 | 暂停无意义的动画播放，提醒调度继续运行 |

点击与拖动必须区分，拖动结束不额外触发点击。按钮、输入框和任务勾选区域不应触发窗口拖动。提醒气泡结束后仍可从任务列表找到未完成任务。

精灵图素材需要约定透明背景、帧宽高、行列、帧数、播放速度、循环规则和角色锚点。首版由开发者接入素材，不包含面向用户的素材编辑器或导入工具。正式分发前记录素材来源与适用授权。

## 7 窗口与本地使用

- 隐藏保留进程和后台入口；重新显示恢复当前任务状态。
- 点击组件关闭按钮时展示三个选择。托盘或菜单栏中的“退出软件”是直接表达退出意图的入口。
- macOS 的系统退出菜单与快捷键遵循退出语义，避免被组件关闭选择反复拦截；此行为在原型中核对。
- 退出时完成必要持久化，但正常操作时即保存，不能只在退出时保存数据。
- 记住窗口位置；显示器断开或分辨率变化后，恢复到当前可见屏幕范围内。
- 重复启动时优先显示已有实例，避免多个调度器重复提醒。
- 安装新版本时保留本地数据；卸载时的数据保留策略在发布阶段明确。

## 8 首版验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 新增今天的一次性任务 | 可查看、编辑、完成、撤销与删除，进度一致 |
| A02 | 每天两次的重复计划 | 今天生成两次独立任务，完成一次不影响另一次；次日重新生成 |
| A03 | 重复计划编辑、暂停、恢复、结束 | 后续安排正确变化，历史完成记录保留 |
| A04 | 跨天 | 日期与今日清单更新；昨日待办保留，未被自动完成 |
| A05 | 将昨日任务移到今天 | 只移动一次，保留原日期信息；今日统计增加一项 |
| A06 | 到点提醒与点击定位 | 在两平台的安装后应用中验证通知及任务定位；关闭通知不完成任务 |
| A07 | 提前完成与提醒去重 | 提前完成后到点不提醒；普通重启不重复提交同一次提醒 |
| A08 | 关闭选择 | 隐藏后进程与提醒保留，退出后停止，取消后窗口保持 |
| A09 | 休眠与恢复 | 当天遗漏事项汇总提示，倒计时恢复正确，不连续补弹旧提醒 |
| A10 | 宠物互动 | 点击、拖动、完成和提醒动作可区分，任务操作不被动画阻塞 |
| A11 | 本地保存与版本替换 | 重启及覆盖安装后数据保留；保存失败可感知，不显示虚假的成功 |
| A12 | 多屏与缩放 | 不出现窗口丢失、按钮不可点或宠物与卡片错位 |
| A13 | 空清单及删除操作 | 无除零或虚假全部完成状态；删除后统计按有效任务更新 |
| A14 | 通知不可用 | 不影响任务操作，能发现通知失败或不可用状态 |

## 9 后续范围与待明确项

后续可增加指定星期重复、稍后提醒、多角色、开机启动、备份导入导出及轻量打卡。账号、跨设备同步和服务端不在当前产品范围内。

原型阶段需明确：界面布局与尺寸、窗口默认是否置顶、正式支持的系统版本与芯片架构、是否需要旧通知在应用退出后点击重新启动，以及未运行期间是否需要补齐所有历史安排。完整桌面游走、跨全屏空间显示和桌面图标层挂载不作为首版默认验收目标。

## 10 优化原型与架构对接

用户接受优化后的原型并进入架构设计。布局与交互采用当前 [HTML 原型](dual-platform-prototype.html) 与 [原型设计](prototype-design.md)；正式实现按 [应用架构](architecture.md) 和 [数据模型](data-model.md) 分离界面、业务与原生能力。

- 纳入完整清单、仅桌宠、后台隐藏三种使用模式。仅桌宠仍保留气泡与今日摘要，后台隐藏继续提醒。
- 采用原型中的日期查看、任务编辑、计划编辑、时间槽增删和气泡直接完成任务。
- 提醒优先于普通互动和完成反馈；气泡与列表操作同一个任务实例。
- 窗口初始尺寸以 356 × 560 逻辑像素为起点，默认置顶并可关闭；仅桌宠的原生边界需要实际缩小，具体尺寸在 M0 验证。
- 原型中的宠物资源选择、参数和导入纳入架构，作为独立扩展批次实现；核心任务闭环仍先接入一套素材，扩展工期单列。
- 已到点、已完成及手动迁移记录按历史保护规则保留。原型示例中的数组清理逻辑不替代正式业务规则。
- 未来日期查看提供计划预览，历史仅展示实际生成记录；简单读取不补造任务。

系统版本、架构与退出后旧通知激活范围仍以安装包验证结果确定。此轮接受的是原型交互，未将模拟托盘、通知或存储标记为原生验收通过。
