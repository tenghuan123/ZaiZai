验证日期：2026-11-02，Asia/Shanghai。实现基于 M0 提交 `1a1bd6f`。目标是让 M2 界面直接消费正式任务事实，替换 M0 样本数据路径。

本页保留 M1 阶段事实。M1 已提交为 `46dae24`；当前界面及回归脚本已继续推进至 [M2](m2-verification.md)，M1 归档证据保持原样。

## 数据位置、升级与恢复

本轮保留 M0 应用身份、包名和用户目录，以原路径承接升级：

- macOS 开发库：`~/Library/Application Support/desktop-buddy-m0-dev/m0.sqlite3`。
- macOS 测试应用包：`~/Library/Application Support/desktop-buddy-m0/m0.sqlite3`。
- 其他平台使用 Electron `appData` 下相应目录；开发与打包身份分离。
- 测试使用 `TIA_M0_DATA_DIR` 隔离；诊断文件仍为 `m0-events.ndjson`，不记录完整任务正文。
- 成功落盘的迁移前备份位于原库旁边，名称为 `m0.sqlite3.pre-v2-<时间>-<UUID>.bak`，其内容仍是旧版本完整库。

旧库升级失败会回滚，启动错误框显示数据库及已完成备份路径，提供“打开数据目录”和“退出”。不会自动改用空库，也不会自动覆盖恢复。

需要手动恢复时，先完全退出应用；将现有库及同名 `-wal`、`-shm` 文件整体保存到另一目录，再复制选定备份为 `m0.sqlite3`。不要在运行中单独删除 sidecar 或用备份覆盖仍打开的库。备份为 v1 时，修复后的新版应用会重新执行迁移；匹配旧版本的应用也可用于读取旧数据。M1 不提供用户备份管理或导出界面。

M0 未保存原始 IANA 时区，升级时只能按电脑当前时区推导旧任务的本地来源日期/时间；原始 UTC 到期毫秒不变。不会猜测原时区或补造过去日期的运行记录。
